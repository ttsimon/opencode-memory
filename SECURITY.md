# Security Policy

## Supported versions

During development, only the current `0.x` release line is supported. Security updates may require upgrading to the latest published `0.x` version.

## Reporting a vulnerability

Use GitHub private vulnerability reporting for this repository as the preferred reporting channel. Include a concise description, affected versions, reproduction steps using synthetic data, potential impact, and any suggested mitigation.

Do not disclose secrets in public issues. Never post credentials, access tokens, private keys, `.env` contents, real user memory, or sensitive configuration in an issue, discussion, pull request, or other public channel. If private vulnerability reporting is unavailable, contact a maintainer privately before sharing sensitive details.

We target a best-effort acknowledgement within 72 hours. This target confirms receipt and begins triage; it does not promise a fix deadline. Remediation timing depends on severity, reproducibility, affected releases, and the safety of the proposed change.
