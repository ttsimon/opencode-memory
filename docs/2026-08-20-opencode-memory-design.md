# OpenCode Memory 设计规格

日期：2026-08-20

## 1. 项目定位

OpenCode Memory 是一个纯本地的 OpenCode 全局插件，为 OpenCode 提供类似 Claude Code 的持久记忆能力，并补充结构化检索、审计和任务续接能力。

系统同时覆盖三类需求：

- 长期记忆：跨会话保存用户偏好、项目事实、架构决策和实践经验。
- 项目规则：维护稳定、可读、可固定注入的项目规则与核心知识。
- 任务续接：保存当前目标、进度、阻塞项、相关文件和下一步操作。

设计文档保留在 `D:\owner\ideas`。实际源码、测试和发布配置将在独立目录 `D:\owner\opencode-memory` 中实施。

## 2. 目标与非目标

### 2.1 目标

- 提供全局与项目隔离的双层记忆。
- 自动提炼值得长期保存的信息，并保持写入过程可审计。
- 固定注入少量核心记忆，按当前对话自动召回相关动态记忆。
- 通过斜杠命令查看、搜索、添加、修改和遗忘记忆。
- 默认拒绝保存密钥、密码、私钥和其他敏感信息。
- 完全本地运行，不依赖云端账号或外部记忆服务。
- 插件故障不得阻断 OpenCode 的正常对话和工具执行。

### 2.2 非目标

以下内容不进入首轮实施范围：

- 云端同步和跨设备同步。
- 团队共享或默认提交到 Git 的项目记忆。
- 独立桌面或浏览器管理界面。
- 依赖外部 embedding 服务的向量检索。
- 后台扫描整个磁盘或项目目录以主动采集信息。

## 3. 核心原则

- 本地优先：所有记忆只保存在本机。
- 自动但不隐形：系统可自动写入，但必须留下来源、时间和变更记录。
- 当前事实优先：当前用户指令、仓库规则和代码事实始终高于历史记忆。
- 最少上下文：只注入稳定核心信息和少量相关结果。
- 敏感信息零落盘：过滤必须发生在数据库、Markdown 和日志写入之前。
- 优雅降级：记忆能力不可用时，OpenCode 仍应正常工作。

## 4. 总体架构

插件由五个边界清晰的模块组成。

### 4.1 Project Resolver

负责识别当前记忆作用域并生成稳定项目 ID。

- Git 仓库以规范化仓库根目录和仓库身份生成项目 ID。
- 同一仓库的子目录和多个 worktree 共享项目记忆。
- 非 Git 目录以规范化绝对路径生成项目 ID。
- 项目 ID 不直接暴露敏感路径信息，可使用稳定摘要作为目录名。

### 4.2 Memory Store

SQLite 是结构化记忆和审计历史的事实来源。

- 保存记忆记录、任务快照、来源关系和审计事件。
- 使用 SQLite FTS 实现第一版全文检索。
- 支持状态迁移、软删除、归档、冲突替代和数据迁移。
- 后续可以增加本地向量检索，但不得改变上层接口。

### 4.3 Markdown Index

Markdown 是便于用户阅读和编辑的投影，不是数据库的并列事实来源。

- 全局和每个项目各维护一个精简的 `MEMORY.md`。
- `MEMORY.md` 只包含高重要度稳定内容和主题索引。
- 详细内容按主题拆分到 `topics/`。
- 用户手动修改 Markdown 后，通过 `/memory-import` 显式预览并导回数据库，避免静默双向同步冲突。

### 4.4 Recall Engine

负责检索、排序、去重、预算控制和上下文注入。

- 固定加载少量全局核心偏好和项目核心规则。
- 检索与当前问题、最近对话主题和当前文件相关的动态记忆。
- 加载当前项目的任务快照。
- 为每条记忆保留作用域、类型、日期和来源标记。

### 4.5 Lifecycle Plugin

通过 OpenCode 插件钩子连接对话生命周期。

- `chat.message`：识别明确偏好、纠正和已确认决策，并准备本轮召回。
- `experimental.chat.messages.transform` 或系统上下文转换钩子：注入筛选后的记忆上下文。
- `session.idle`：执行会话收尾提炼并更新任务快照。
- `experimental.session.compacting`：要求压缩摘要保留任务状态、关键决策和下一步。
- `command.execute.before`：实现和增强记忆管理命令。
- 插件应使用当前 OpenCode SDK 实际暴露的事件类型；实施前以安装版本的类型定义和官方文档为准。

## 5. 数据位置

逻辑目录结构如下：

```text
<local-data>/opencode-memory/
├── memory.db
├── backups/
├── global/
│   ├── MEMORY.md
│   └── topics/
└── projects/
    └── <project-id>/
        ├── MEMORY.md
        └── topics/
```

Windows 使用当前用户的本地应用数据目录。项目记忆默认不写入项目仓库，也不自动进入 Git。

## 6. 记忆模型

每条结构化记忆包含以下字段：

```text
id
scope             global | project
project_id        全局记忆为空
kind              preference | rule | fact | decision | insight | task
content
status            active | superseded | archived | deleted
confidence
importance
source_session_id
source_message_id
created_at
updated_at
last_recalled_at
recall_count
expires_at
supersedes_id
```

字段约束：

- `confidence` 表示提取与分类的可信度，不代表内容客观正确。
- `importance` 决定固定投影和召回优先级。
- `source_session_id` 与 `source_message_id` 用于追溯和幂等处理。
- `supersedes_id` 记录新记忆替代旧记忆的关系。
- 软删除记录不参与召回，但可通过历史查询恢复。

## 7. 作用域规则

### 7.1 全局记忆

只保存跨项目稳定适用的信息，例如：

- 语言和沟通偏好。
- 通用编码风格偏好。
- 常用工具和工作流偏好。
- 用户明确声明的跨项目规则。

### 7.2 项目记忆

保存只属于当前仓库或目录的信息，例如：

- 架构事实和命名约定。
- 构建、测试和部署命令。
- 已确认的设计决策及原因。
- 调试经验和已知陷阱。
- 当前任务状态和后续步骤。

不确定作用域时默认保存为项目记忆，避免跨项目污染。

## 8. 写入生命周期

### 8.1 即时沉淀

以下高价值事件可在对话过程中增量提取：

- 用户明确要求以后遵循某项偏好。
- 用户纠正模型并表明该纠正具有持续性。
- 用户确认架构、技术或流程决策。
- 调试过程中确认了难以从代码直接推导的根因或解决办法。

### 8.2 会话收尾

会话进入空闲状态时提炼：

- 已完成事项。
- 未完成任务和阻塞项。
- 修改或关注的关键文件。
- 已确认决策。
- 值得复用的经验。
- 推荐的下一步操作。

### 8.3 上下文压缩

压缩前向 OpenCode 的 compaction 上下文增加明确要求：

- 保留当前任务目标和状态。
- 保留关键决策及原因。
- 保留阻塞项、风险和下一步。
- 不把敏感信息复制到摘要或记忆候选中。

### 8.4 写入管线

所有候选记忆必须依次经过：

1. 内容分类。
2. 作用域判断。
3. 敏感信息过滤。
4. 质量与置信度判断。
5. 去重和相似项合并。
6. 冲突检测。
7. SQLite 落盘。
8. 审计事件记录。
9. 必要时更新 Markdown 投影。

高置信且明确的信息可以自动保存。低置信候选不自动落盘，避免错误记忆累积。

## 9. 更新、冲突与过期

- 相同或高度相似的记忆优先更新现有记录，而不是新增重复项。
- 新事实与旧事实冲突时，新记录指向被替代记录，旧记录变为 `superseded`。
- 偏好和规则默认不过期，除非被用户修改或明确替代。
- 任务状态完成后归档，不作为当前任务注入。
- 临时环境事实可以设置 `expires_at`，过期后不参与自动召回。
- 系统不得仅因长期未召回就永久删除记忆。

## 10. 任务续接

每个项目最多维护一个活动任务快照，包含：

```text
目标
当前状态
已完成事项
正在处理的事项
相关文件
关键决策
阻塞项与风险
下一步
更新时间
来源会话
```

新会话首次处理当前项目时，可以注入该快照。用户明确开始不相关的新任务后，应归档旧快照并创建新快照，不能把多个任务混成一份状态。

## 11. 召回策略

每次用户发送消息后执行：

1. 识别当前项目和会话。
2. 加载全局核心偏好。
3. 加载项目核心规则。
4. 从用户消息、最近主题和当前文件构造 FTS 查询。
5. 检索项目动态记忆，必要时补充全局动态记忆。
6. 加载当前任务快照。
7. 去重、排序、裁剪并注入上下文。

排序参考：

```text
相关度 × 作用域权重 × 重要度 × 新鲜度 × 置信度
```

默认预算：

- 全局核心偏好最多 8 条。
- 项目核心规则最多 12 条。
- 相关动态记忆最多 8 条。
- 当前任务快照最多 1 份。
- 总注入预算约 2,000 Token。
- 没有相关结果时不注入动态记忆。

注入格式：

```markdown
<opencode-memory>
以下是可能相关的历史记忆，不一定仍然有效。
当前明确指令、项目文件和代码事实优先。

- [项目/决策/2026-08-20] ...
- [全局/偏好/2026-08-18] ...
</opencode-memory>
```

冲突优先级：

```text
当前用户指令
> 当前仓库中的明确规则
> 项目记忆
> 全局记忆
> 历史任务状态
```

模型发现记忆与当前代码或明确规则不符时，应以当前事实为准，并生成纠正候选。

## 12. 管理命令

完整产品命令规划：

```text
/memory
/memory-status
/memory-search <关键词>
/memory-show <id>
/remember <内容>
/forget <id 或关键词>
/memory-edit <id>
/memory-restore <id>
/memory-history [id]
/memory-enable
/memory-disable
/memory-export
/memory-import
/memory-doctor
```

本次实施范围内，MVP 提供 `/memory`、`/memory-status`、`/memory-search`、`/memory-show`、`/remember`、`/forget`、`/memory-enable` 和 `/memory-disable`；自动记忆阶段增加 `/memory-history` 与 `/memory-doctor`。`/memory-edit`、`/memory-restore`、`/memory-export` 和 `/memory-import` 属于后续增强。

行为约定：

- `/memory` 展示当前作用域、核心记忆、最近写入和当前任务。
- `/remember` 自动判断作用域，并在结果中明确显示最终分类和作用域。
- `/forget` 遇到多条匹配时不得猜测删除，必须要求指定 ID。
- 删除默认采用可恢复软删除。
- `/memory-edit` 产生新的审计版本，不覆盖历史证据。
- `/memory-restore` 恢复被软删除的指定记录。
- `/memory-export` 导出可读 Markdown，不包含已过滤内容。
- `/memory-import` 先展示新增、更新和冲突预览，再执行导入。
- `/memory-status` 显示本轮注入、最近写入和插件降级状态。
- `/memory-doctor` 检查数据库、索引、迁移、项目识别、权限和投影同步。

如果 OpenCode 的自定义命令机制无法直接承载交互行为，则命令文件只负责把请求路由到插件提供的结构化工具，数据库操作仍由插件完成。

## 13. 用户反馈与审计

- 自动保存后显示简短反馈，例如“已保存 2 条项目记忆”。
- 自动召回默认静默，避免每轮对话产生噪声。
- 用户可通过 `/memory-status` 查看本轮实际召回内容。
- 审计记录包含触发会话、来源消息、作用域、类型、变更摘要和状态迁移。
- 合并、替代、归档、恢复和删除必须保留关系记录。
- 敏感过滤事件只记录类型和拒绝原因，不记录原文、哈希或可逆摘要。

## 14. 安全设计

### 14.1 硬过滤内容

- API Key 和访问令牌。
- 密码和认证 Cookie。
- 私钥、助记词和证书私密材料。
- 数据库连接字符串中的凭据。
- `.env` 文件内容和常见秘密配置。
- 身份证件、支付信息、个人隐私和客户敏感数据。

### 14.2 安全约束

- 过滤发生在所有持久化与日志操作之前。
- `/remember` 不能绕过硬过滤。
- 不保存敏感原文、哈希或可逆摘要。
- 插件不后台扫描整个磁盘。
- 插件只处理当前对话、显式工具结果和用户明确导入的内容。
- 数据目录仅允许当前操作系统用户访问。
- 导出和诊断信息必须再次经过脱敏检查。

## 15. 故障与恢复

- 所有生命周期钩子捕获内部异常，不阻断正常对话和工具调用。
- 数据库锁定、损坏或迁移失败时降级为无记忆模式，并仅显示一次警告。
- Markdown 投影失败不回滚 SQLite 事实记录，后续可以重建。
- 自动提炼失败时保留不含敏感原文的待处理事件，并在下次空闲时有限重试。
- 通过会话 ID、消息 ID 和操作类型实现事件幂等。
- 数据库迁移前创建备份，并默认保留最近三个版本。
- `/memory-doctor` 应提供可执行的恢复建议，但不得自动执行破坏性修复。

## 16. 测试与验收标准

### 16.1 项目隔离

- Git 仓库根目录、子目录和 worktree 映射到同一项目记忆。
- 不同仓库不会互相召回项目记忆。
- 非 Git 目录根据规范化路径稳定隔离。
- 全局偏好能够跨项目召回。

### 16.2 写入与生命周期

- 明确偏好和确认决策能够自动沉淀。
- 会话空闲时能够更新任务快照。
- compaction 能保留任务状态和关键决策。
- 重复事件不会产生重复记忆。
- 低置信候选不会静默写入。

### 16.3 检索与冲突

- FTS 能召回与当前请求相关的记忆。
- 召回严格遵守条数和 Token 预算。
- 无关项目记忆不会进入上下文。
- 新事实可替代旧事实，并保留审计历史。
- 已删除、归档和过期记录不参与普通召回。

### 16.4 安全

- API Key、密码、私钥、连接凭据和 `.env` 内容永不落盘。
- 敏感原文不会出现在数据库、Markdown、日志、备份或导出中。
- 诊断命令不会泄露被过滤内容。

### 16.5 故障降级

- 数据库不可用时 OpenCode 仍可正常对话和调用工具。
- Markdown 投影损坏后可以从 SQLite 重建。
- 迁移失败可以使用备份恢复。
- 插件只对同一故障显示一次非阻断警告。

### 16.6 管理能力

- 本次实施范围内，用户能查看、搜索、添加和软删除记忆，并查看变更历史。
- 歧义删除不会误删记录。
- 所有变更均可从审计历史追溯。

## 17. 分阶段交付

### 17.1 MVP

- SQLite 数据模型和 FTS。
- 项目识别与双层作用域。
- `/memory`、`/memory-status`、`/memory-search`、`/memory-show`、`/remember`、`/forget`、`/memory-enable` 和 `/memory-disable`。
- 核心记忆注入。
- 敏感信息硬过滤。
- 当前任务快照。

### 17.2 自动记忆

- 增量候选提取。
- `session.idle` 收尾提炼。
- compaction 集成。
- 去重、冲突替代和 Markdown 投影。
- 审计历史、`/memory-history` 与 `/memory-doctor`。

### 17.3 后续增强

- `/memory-edit`、`/memory-restore`、`/memory-export` 和 `/memory-import`。
- 本地向量或混合检索。
- 可选 Git 团队记忆。
- 可选跨设备同步。

本次产品目标覆盖 MVP 和自动记忆两个阶段。后续增强不属于本次实施承诺。

## 18. 实施边界

- 设计资产保留目录：`D:\owner\ideas`。
- 独立项目目标目录：`D:\owner\opencode-memory`。
- 本规格已同步到目标目录的 `docs/2026-08-20-opencode-memory-design.md`；后续在目标目录初始化独立仓库并实施。
- OpenCode 全局配置只在插件具备基础测试和可降级能力后修改。
- 修改全局插件或配置后必须退出并重新启动 OpenCode 才能生效。
